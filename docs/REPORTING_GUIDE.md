# 공통 기술보고서 작성 규칙 (SSOT)

Claude와 Codex는 보고서 생성·수정 및 보고서 생성기 변경 시 이 문서를 반드시 따른다. 적용 대상은 결과보고서, 분석근거 문서 및 보고서용 요약이다. 계산 모델·입력·규격의 SSOT는 기존 ICD와 데이터이며, 이 문서는 표현과 구성의 SSOT다.

## 1. 결과를 먼저 제시한다

첫 문단에서 결론, 핵심 수치, 물리적 의미, 판정 범위를 밝힌다. 각 섹션도 결과나 판단으로 시작하고 근거를 설명한다. 긴 원시 데이터 설명만 이어지는 섹션을 만들지 않는다. 구현·실행 이력보다 독자가 판단해야 할 결과를 앞에 둔다.

RFI 결과보고서의 기본 순서는 다음과 같다. 산출하지 않은 항목도 생략하지 말고 미평가 이유와 필요한 입력을 짧게 적는다.

1. Executive Summary
2. 주요 RFI 결과 / 요구 억제도 / margin
3. Victim-band PSD 결과
4. Receiver criterion
5. Filter / suppression requirement
6. 입력 누락 및 분석 한계
7. Secondary blocker analysis
8. Appendix / detailed validation

## 2. Executive Summary

핵심 결론과 대표 worst case를 먼저 쓰고, 계산 완료 범위와 미판정 범위를 구분한다. 중요 수치에는 단위, 평가 위치·대역, 의미를 붙인다. 전체 적합 여부와 특정 모델 안의 결과를 구분한다. 미확정 입력 때문에 최종 판정이 보류된다면 필요한 입력을 명시한다. 구현 상세, 코드 변수명, hash, CSV 행 목록은 넣지 않는다.

## 3. 표와 중복

표는 핵심 결과·기준·가용성의 비교에만 쓴다. 일반적으로 3~7열을 사용하고, 15열 이상은 금지한다. CSV 행을 그대로 Markdown 표로 옮기지 않는다. 대표 worst case와 결론을 바꾸는 차이만 본문에 남긴다. 동일 pair의 case별 반복은 적용 범위를 명시해 묶되 수치나 가정이 다른 행을 임의로 합치지 않는다. 상세 전체 행은 CSV 링크와 조회 키로 안내한다. 표 뒤에는 순위의 적용 범위와 물리적 의미를 설명한다.

## 4. 숫자·단위·근거 유형

전력은 dBm 또는 W, PSD는 dBm/Hz, 상대 억제량·margin은 dB, 이득은 dBi로 구분한다. 표 머리글에 단위를 쓰고 본문 수치에도 붙인다. 주파수·대역폭·기준면(TX 포트, victim 포트, 필터 전/후 등)을 명시한다. dBc/Hz에는 기준 반송파 전력과 기준면을 붙인다. 단위 변환·반올림은 표시 목적에 한정하고 원본 CSV 정밀도를 유지한다. 로그 전력을 직접 합하지 않는다.

중요 입력과 결과에는 다음 근거 유형을 문장 또는 표에서 명시한다.

- **가정 (assumption):** 임시 운용, 이상 필터, 자유공간 등의 모델 가정. 적용 범위와 한계를 적는다.
- **실측 (measured):** 실제 측정값이며 출처·조건·기준면을 적는다. CST 등 solver 출력은 **시뮬레이션 데이터**라고 별도 표기하며 실측으로 부르지 않는다.
- **규격 (spec):** 승인된 요구값과 문서 출처. 임시 engineering baseline은 가정/잠정 기준이라고 밝힌다.
- **산출 (derived):** 입력과 모델로 얻은 값. 출처와 핵심 관계식을 연결한다.
- **미확정:** 값이 확보되지 않았거나 승인되지 않은 상태. 필요한 자료를 적고 0 또는 임의 이득으로 대체하지 않는다.

## 5. 판정·누락 상태를 사람이 읽을 수 있게 쓴다

PASS는 “해당 기준 충족”, FAIL은 “해당 기준 초과”, UNKNOWN은 “최종 판정 보류”로 표현하고, 대상·기준·가정·근거를 함께 밝힌다. 미평가는 계산하지 않았다는 뜻이며 실패와 구분한다. solver 검증 PASS를 RFI 적합 PASS로 확대하지 않는다.

INPUT_MISSING은 “입력 미확보로 계산/판정 보류”라고 쓰고 누락 입력, 완료된 계산, 막힌 평가를 설명한다. 예: “Victim-band coupling은 계산 완료, TX emission 규격 미입력으로 최종 판정 보류”. 원본 `EMISSION_MASK_MISSING_COUPLING_EVALUATED` 등 enum은 필요할 때 Appendix에서만 연결한다.

NaN은 미확보/미평가 이유로 바꾼다. −Inf dBm이 모델의 0 W를 뜻한다면 “이상 모델에서 0 W”로 설명한다. +Inf margin을 실제 무한 여유로 보고하지 않는다. 누락 경로를 제외한 합산은 “확보 경로만의 부분 합산”으로 표시한다.

Margin은 비교 대상·기준면·부호를 정의한다. 일반적으로 허용치−결과이며 양수는 여유, 음수는 초과다. 다른 정의를 쓰면 명시한다. 미확보 입력에 대해 margin이나 요구 억제량을 만들어 내지 않는다.

## 6. Victim-band PSD와 blocker를 분리한다

Victim-band PSD는 **수신기 tuning 대역에 존재하는 TX 불요방사**를 해당 주파수의 결합과 함께 평가한 dBm/Hz 결과다. TX 기본파 주파수에서 구한 필터 전 적분 전력(dBm)은 **대역 외 blocker 노출**이며 이를 victim-band PSD로 대체하지 않는다.

Receiver criterion은 PSD mask, 채널 적분 I/N, C/N0, J/S, blocking·compression 등 기준별로 구분한다. 어떤 기준을 실제 평가했고 무엇이 미평가인지 밝힌다. 기본파 비중첩만으로 불요방사·스퍼·고조파·비선형 영향을 통과 판정하지 않는다.

필터 요구에는 TX 불요방사 억제와 RX blocker rejection을 구분하고 적용 주파수·기준면·실제 필터 데이터 유무를 적는다. “blocker 전력−수신 대역 내 간섭 허용치”는 진단용 screening 차이이며 검증된 RX OOB rejection 요구값으로 부르지 않는다. 대표 blocker는 Summary에서 핵심 위험만 알리고 상세는 Secondary blocker analysis에 둔다.

## 7. 본문과 Appendix·CSV의 역할

본문은 사람이 판단할 수 있는 결론·비교·물리적 해석·제약을 제공한다. machine-readable CSV는 전체 정밀도, 전체 pair/case, enum, 중간 결과와 자동 검증용 근거를 보존한다. 둘을 서로 대신 사용하지 않는다.

메인 결론에 직접 필요하지 않은 Ka near-field, solver validation, mesh 상세, 좌표 변환, 보간 구현, 수렴 grid, hash/commit 이력은 Appendix 또는 별도 근거 문서로 보낸다. 결론을 제한하는 근거리 모델·mesh 한계 자체는 본문에 짧게 남긴다. 파일·commit·hash 출처는 Appendix 한곳에 모으고 본문 여러 곳에서 반복하지 않는다. 소스 변수명 대신 물리적 용어를 사용하고 필요할 때 Appendix에 매핑한다.

## 8. Claude/Codex 공통 준수

스타일 참조는 수치의 권위가 아니다. 각 worker는 자신의 기존 산출물과 provenance를 유지한다. 다른 worker의 수치·해석·모델을 자신의 결과로 복사하지 않는다. 최신 입력 파일 상태를 과거 실행 당시 입력 상태로 서술하지 않는다.

편집 완료 시 구조, 수치/단위 보존, 대표값 출처, 판정 범위, 누락 사유, 중복 축약, CSV 링크를 확인한다. 표현 정리만 요청받았다면 계산·시뮬레이션을 재실행하지 않는다. 재사용하는 과거 검증 결과와 이번 편집 검증을 구분한다. 기존 생성기가 이 guide와 다르면 재사용 전에 출력 구성을 수정하고 원본 결과와 입력 snapshot을 보호한다.
