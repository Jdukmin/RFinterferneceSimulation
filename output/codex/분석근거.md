# 분석 근거 파일 안내

## Task 2: 최신 scope와 조회 경로

현재 primary에는 S-TC TX / Ka DLS TX만 포함하며 ISL/SAR attacker는 제외한다. [task2_role_matrix.csv](task2_role_matrix.csv)와 [task2_scope_exclusions.csv](task2_scope_exclusions.csv)를 참조한다. 이전 inclusive 분석과 KAA 저주파 gain bound는 legacy/sensitivity이며 현재 Ka cutoff primary와 구분한다.

SAR harmonic 여부는 [sar_harmonic_overlap.csv](sar_harmonic_overlap.csv), 일반 spurious는 [stc_sar_spurious_results.csv](stc_sar_spurious_results.csv)에서 조회한다. SAR normalized reconstruction과 미확정 peak gain을 구분한다. WR-42 TE10 cutoff/dB-per-mm는 [ka_cutoff_band_results.csv](ka_cutoff_band_results.csv), victim transfer와 최소 유효 길이 요구식은 [ka_cutoff_pair_requirements.csv](ka_cutoff_pair_requirements.csv)다. 총 EIRP를 임의 bandwidth로 나누지 않았으며 ITU spurious 4 kHz envelope를 source PSD의 근거로 유지했다. Effective length/reference-plane 확인 전 cutoff credit은 없다.

## Task 1: owner port-mismatch rescaling

L1의 기존 source/coupling을 유지하고 L2/L5만 owner 승인 −10 dB mismatch와 기존 conservative radiation envelope를 적용했다. ITU source −49.0206 dBm/Hz → accepted-power 상당 source −59.0206 dBm/Hz → radiation gain envelope 9.03 dBi → EIRP screening −49.9897 dBm/Hz → 정상 GPS receive RealizedGain / FSPL → victim port 순서다. Mismatch와 gain을 중복 적용하지 않는다.

[task1_lband_pair_results.csv](task1_lband_pair_results.csv)에서 primary engineering route를, [task1_cst_normalization_evidence.csv](task1_cst_normalization_evidence.csv)에서 사용하지 않은 CST 절대 gain과 accepted-power fraction을 확인한다. [task1_validation.json](task1_validation.json)은 L1 regression, 10 dB 정확한 감소, source 산술, 모든 filter scenario를 검증한다. 이전 UNKNOWN 기록은 과거 진단이며 Task 1의 L2/L5 정량 engineering 결과와 구분한다.

[conditional_bound_required_suppression.csv](conditional_bound_required_suppression.csv)는 같은 키의 조건부 gain envelope이며, primary 미판정을 대체하지 않는다. 이번 보완은 기존 Codex freeze coupling을 재사용한 Python 산술 계산이다. CST/Octave 분석을 재실행하지 않았다. [suppression_design_validation.json](suppression_design_validation.json)에 공유 입력 hash와 이전 ITU regression의 차이 0 dB, 식·시나리오 검증을 기록했다. 이전 ECSS primary와 최신 ITU source를 구분해야 하며, 이후 안내는 과거 분석의 조회 방법이다.

## 현재 규격 기반 독립 분석

Freeze 상태는 `freeze_record.json`, 사용 공유 입력의 hash는 `emission_inputs/freeze_input_hashes.csv`다. 공식 문서 확인 근거는 `standard_source_evidence.csv`, 규격 선택 비교는 `standard_candidates.csv`, 실제 숫자 변환은 `source_derivation.csv`와 `emission_inputs/tx_emission_masks.csv`에서 확인한다.

1. `victim_band_scenarios.csv`에서 `case_id`, `tx_id`, `rx_id`, `source_set`, `filter_db`를 찾는다.
2. 같은 경로의 `worst_frequency_hz`를 `victim_band_coupling.csv`에 대조한다. `source_set=PRIMARY`와 gain-cap sensitivity를 구분한다.
3. 해당 TX/victim의 source table에서 기준면·RBW·공식 조항·broadband/tone 구분을 확인한다.
4. `pair_filter_requirements.csv`에서 0 dB margin과 총 최소 추가 억제량을 확인한다. 이 값은 scenario 필터를 추가하기 전의 총 요구량이다.
5. `emission_validation.json`과 `emission_execution.log`에서 검증을 확인한다. Discrete spur는 `discrete_spur_results.csv`에서 dBm 전력으로 조회한다.

아래 기존 안내는 보존된 기본파/blocker 결과의 조회 방법이다. 새 primary filter 요구는 해당 기본파 값에서 도출하지 않는다.

보고서 작성은 [공통 reporting guide](../../docs/REPORTING_GUIDE.md)를 따른다. 최신 추가 억제 식은 결과보고서의 Source·기준면·required suppression 정의에서 확인한다.

어떤 패턴을 어떤 케이스에 적용했는지는 `case_pattern_evidence.csv`에서 확인한다. 기본 baseline pattern key/원본 XZ·YZ/설치/역할/활성 집합을 케이스와 시나리오별로 기록했다.

실제 주 RFI 계산에서 사용한 대역별 pattern은 `frequency_direction_evidence.csv`의 tx_source/rx_source/quantity이다. baseline key만 보고 해당 baseline이 모든 대역의 주 계산에 사용되었다고 해석하지 않는다. S/L/ISL에는 해당 대역 CST RealizedGain을 사용했고 Ka에는 frozen reflector reference gain을 사용했다. 미확보 응답은 `rfi_pairs.csv`의 missing_reason으로 확인한다.

1. case_pattern_evidence.csv에서 case_id, mode_id, function_id를 찾는다.
2. rfi_pairs.csv에서 같은 케이스의 TX/RX 경로와 방향을 찾는다.
3. frequency_direction_evidence.csv에서 실제 평가 주파수·원본 CSV·CST source case·이득 종류·S21을 대조한다.
4. input_hash_manifest.csv에서 원본 hash를 확인하고 input_snapshot의 RF 입력을 대조한다.
5. 결과보고서.md의 계산식과 octave_execution.log를 확인한다.

안테나 CAD/포트/원본 frozen 패턴을 변경하지 않았다. 설치 패턴은 사용하지 않았으며 기존 S 국부 구조 결과도 final로 승격하지 않았다. SAR는 별도의 응답/EIRP 민감도만 수행했다. CSV 숫자는 Octave 출력이며 Python 보고서 작성이 RF 계산을 대체하지 않았다.
